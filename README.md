# Dungeon Heart — Backpack Trap Defense

Мобильный 9:16-прототип, в котором backpack-поле одновременно является процедурным подземельем. Между волнами игрок свободно упаковывает ловушки на открытом полу, собирает направленные синергии и крупными `Expand` раскрывает новые комнаты. В бою 1–3 потока врагов проходят через широкие контрольные зоны и естественно растекаются по комнатам к Dungeon Heart.

## Основной контракт

- Ставить ловушки можно на любую открытую клетку пола; настенных ловушек нет, ловушки не блокируют движение.
- Все десять footprint-форм гарантированно помещаются на стартовом поле без учёта уже установленных предметов.
- При создании стейджа случайно выбирается один из авторских layout; он раскрывается четырьмя крупными Expand, а старые комнаты не перестраиваются.
- Прогноз трафика в подготовке показывается анимированными стрелками поверх ловушек и использует те же авторские порталы, что бой.
- Бюджет каждой волны поровну делится между активными порталами. Красные стрелки и spawn врагов находятся за открытым полом; враги выходят из тумана через соседнюю входную клетку. Летуны следуют общему потоку, но не активируют напольные Plate-ловушки.
- Сила растёт детерминированно от ловушек, тиров, стихийных перков и направленных buff-зон. Экономических и защитных ловушек нет.

## Запуск

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173/`. Мышь повторяет touch-ввод; игра сохраняет композицию 9:16.

## Управление

- Перетащите ловушку из магазина на светлый пол. Если footprint пересекает другой предмет, тот возвращается в магазин: тупиковых покупок нет.
- До боя все ловушки можно свободно переставлять. Карточка с действием, стихией и синергией показывается во время drag.
- `Expand` раскрывает следующий заранее сгенерированный участок подземелья; `Reroll` меняет предложение магазина; `Battle!` запускает волну.
- После волн с перком выберите одну из трёх стихийных модификаций.

## Проверки

```bash
npm test -- --run
npm run build
```

Property-тесты проверяют сотни seed: детерминированный выбор авторского layout, четыре монотонных reveal, внешние spawn-точки, связность, трафик по полезной площади, вместимость всех footprint, точные тэги/зоны и равный spawn-бюджет.

Текущая реализация пивота находится в `src/game/pivot/`; прежняя экспериментальная система в `src/game/` оставлена только как изолированный legacy-код и не подключена к приложению.

Новые карты добавляются в `src/game/pivot/layouts.ts`: восемь символов в каждой из 12 строк, где `1` — стартовый пол, `2`–`5` — очередные Expand, `#` — скала, `H` — Heart. Для каждого из пяти состояний там же задаются пары `spawn`/`entrance`; spawn обязан находиться вне открытого пола и соседствовать с входной клеткой.
